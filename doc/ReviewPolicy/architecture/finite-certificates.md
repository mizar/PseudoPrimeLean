# 有限認証

`CERT-01`：候補データ、checker、checkerの健全性定理、用途別の適用定理を異なる役割として扱う。それぞれが何を生成・検査・証明するかを確認し、一般の理論と用途固有の認証を区別する。

`CERT-02`：供給された各要素が条件を満たす健全性と、必要な要素が列挙に含まれる完全性を区別する。必要な範囲と端点、重複、素数冪などの指数が、利用側の主張に合っていることを確認する。

`CERT-03`：数表を拡張するときは、可能なら既存prefixの正しさを再利用して追加部分を認証する。再利用の前提と接続部分を確認し、範囲全体の完全性が必要なら別途示す。

`CERT-04`：一般理論や共通checkerから具体的な用途別数表をimportしない。ファイルの分割に加えて、集約importを含む直接・推移依存を確認する。配置の判断には [一般化と所有者](generality-ownership.md) と [ソース配置と依存](placement-imports.md) も適用する。

`CERT-05`：外部生成器は候補データの生成に用い、数学的主張はLeanカーネルで検証する。生成器の実行成功、外部計算の結果、Leanで検証した範囲を区別する。

`CERT-06`：有限検査や区間検査では、数表、巨大な型、検査結果の中間表現を証明用の実装として扱う。区間定理や分類別の累積定理の利用側には、原則として必要な定理とその型に必要なAPIだけを公開する。数表や中間宣言を公開する場合は、独立した利用目的を確認する。

区間統合ファイルは個別の数表を直接importせず、原則として各区間の定理をimportする。証明のために数表を使う区間ファイルでは、利用側が必要としない数表のimportを再公開しない。統合定理の型や定義本体に巨大なデータが露出していないかも確認する。数表を再公開しないことと、その検証済みの定理に依存することは両立する。
