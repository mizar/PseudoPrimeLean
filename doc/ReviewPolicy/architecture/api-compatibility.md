# APIと互換性

`API-COMPAT-01`：改名、所有者移設、モジュール移動では、原則としてプロジェクト内の利用側を同時に更新し、旧APIの互換alias、互換用ラッパー、転送importを残さない。旧経路を維持する必要がある場合は、例外として扱う。

`API-COMPAT-02`：具体的な外部利用または段階的移行が必要な場合に限り、理由、対象、廃止条件を記録して例外を設ける。既存の互換経路をこの規則だけで一括削除しない。

`API-COMPAT-03`：互換性のために新たな逆依存や循環依存を作らない。既存の利用側、完全修飾名、定理の型、import経路を移行前後で確認する。

`API-COMPAT-04`：新しい定義の利用方法に応じて特徴付け定理、属性、可視性を選ぶ。必要性のない別名を追加しない。

所有者移設の方針は [一般化と所有者](generality-ownership.md)、依存の確認は [移設手順](../exceptions/namespace-migrations.md) を参照する。
